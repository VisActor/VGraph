# 血缘图谱-表视图

## 场景介绍
数据加工处理的流程一般是从 RDS 和 MQ 开始，经过多次多种计算和存储，最终汇入指标、报表和数据服务系统。数据血缘描述了数据的来源和去向，以及数据在多个处理过程中的转换。能帮助用户更好地了解表，从而充分利用数据。当用户关注某个字段或者要修改某个字段时如果能仅查看与此字段相关的血缘关系，能提高使用效率，优化体验。使用文档请见[血缘图谱文档](../analysis-solution-spec/dataLineage)。


## 场景编码
**布局**: 沿用了表视图的布局，设计思考可见表视图 demo 用法文档。


**元素**: 由于在不同产品视觉风格不同，节点内容差异较大。因此组件支持用 React 组件定制节点。详情可见`getTableContent` 配置项。在列视图中应不仅展示字段数据，也应展示字段归属的表数据。组件也支持用 React 组件定制分组头样式，详情可见`getGroupContent` 配置项。 

**交互**:
1. click 字段：血缘图谱场景下由于数据众多，在默认视图下看清节点之间的链路关系还是比较困难的。组件默认添加了点击节点高亮字段到主节点的全部路径。让用户可以通过滚动定位在一屏中看清任意节点的链路关系。
2. hover 连线：在血缘图谱场景下，连线不仅仅是表示两者之前的依赖关系，也是承载字段之间加工逻辑关系的良好载体。因此组件支持定制 hover 连线的 tooltip 内容，详情可见配置项`getTaskTooltipContent`。

## 设计思考
如果说要支持万级数据量的表血缘关系已经非常艰难，而这万级数据对应的全量列视图的数据量则是几十万。如果一次性将所有数据全部展示出来，会为用户增添很多无用的字段数据干扰。因此在使用列视图时推荐默认展示一个字段的血缘，通过 Toolbar 或图中节点交互让用户自行选择关注的字段血缘是一种更清晰直观的展示方式。Coral 血缘图谱的列视图即是采用了这种方式。首先在 Toolbar 上能选取主节点字段，也可以 hover 到主节点字段中勾选感兴趣的字段。
