# 关系图

关系图数据是一种更一般化的网络数据，不同于 DAG 图的拓扑排序特性，关系图表达的内容更加自由和复杂。它存在于生活的方方面面，自然的反映着现实世界，如生物基因网络、社交好友网络等。

## Demo - 知识图谱

### 数据释义

知识图谱是结构化的语义知识库，用于描述各个事物的概念及其相互关系。demo 中选取了红楼梦人物关系的知识图谱数据，该数据中包含了红楼梦中的主要人物名称、所在家族以及人物之间的关系类型，如父亲、姐妹等。

### 场景编码

**布局：** 力导布局。

**元素：** 图中的每个节点代表红楼梦中的一位人物，节点的颜色表示该人物来自的家族；节点之间的有向边表示人物之间的关系，有向边上的文字则表明了具体的关系类型，如从贾母到林黛玉的箭头连线标明外孙女，则说明贾母的外孙女是林黛玉。
 
**交互：** 

1. pan + zoom 画布：放大画布展示节点上的具体人物名字
2. hover 节点：高亮节点相邻节点，展示与人物相关的全部人物，当画布缩放超过一定比例时，详细展示具体的关系类型
3. click 图例：筛选某一家族的人物群体，聚焦了解该家族的人物关系

**组件：**

1. Legend ：说明节点颜色所代表的对应人物家族

### 设计思考

* 知识图谱中节点与边关系复杂且有着具体的语义，当画布缩放比例较小时，图中存在着大量的遮挡关系，导致信息不可读。为了解决这一问题，demo 中的关系图使用了放大展示细节的方式。在关系图的一开始可以对整个知识图谱进行概览阅读，当需要了解详细信息时，通过放大画布的交互进行按需查看细节。在放大展示细节的过程中，我们控制文本和箭头的大小不变，只是节点大小和节点间的距离在不断扩大，配合文字的反色描边，显著的增强了信息的可读性。
* 在图信息规模大、复杂度高的场景时，可以使用概览展示结构、局部呈现信息的搭配方式进行呈现；首先根据需求目标判断初始状态呈现概览或是细节，之后提供相应的放大展示细节或者缩小隐藏细节的交互操作，这可以有效的帮助用户获取信息。
* 知识图谱中人物之间的关系是相互的，如贾母是林黛玉的外祖母，林黛玉同时也是贾母的外孙女，这就存在节点之间边的双向关系。为了避免边的重叠， demo 中使用了 quadratic 连线类型；曲线的配置可以用于当连线没有实际的物理意义，又需要解决节点间连线路径重合的情况。
