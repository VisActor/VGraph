# 实例血缘-通用模式

## 场景介绍
数据加工处理的流程一般是从 RDS 和 MQ 开始，经过多次多种计算和存储，最终汇入指标、报表和数据服务系统。任务实例血缘描述了数据加工任务实例之间的相互关系。概括来说，任务实例血缘图的应用场景有三种：
- 关系展示：以用户关心的节点为中心，查看该节点的上下游依赖。
- 上游分析：当节点运行出现异常，向上追溯问题，关注的是**关系链路**。
- 下游分析：分析节点的下游影响面，此时关注的是**统计数据**。

通用模式对应图中第一种场景，用户可以自由向上向下展开依赖的任务，更好的理解聚焦的节点。使用文档请见[实例血缘文档](../solutions/commonInst)。


## 设计思考
由于任务的实例一般很多(例如一个小时调度的任务，一天即可产生 24 个任务实例。一个任务实例的直接上游就可能有数万个节点)，如果单层一字铺开图像很大，再加上焦点丢失就很难进行更多操作了。我们需要一种更聚焦的方式来展示节点之间的关系，帮助用户理解和分析。
通用模式中节点会分层展示，为了更好的分析连续型，在展开/收起节点的上/下游时会固定当前操作节点的相对位置，保证视图刷新后焦点位置不变。此场景下的用户都很关注实例节点的运行状态，因此当某个节点的直接上/下游节点超过 10 个时就会收起所有明细节点显示一个统计节点(最大明细节点展示数量可配置)。统计节点会展示出节点的状态和数量，用户可以直接点击数量快速展开节点继续探索。为了让关系展示更聚焦，本方案支持收起单个节点和收起所有上/下游，整个图在视觉上更简洁。

## 场景编码
**布局**: 采用了 [DAGLayout](../layout-spec/dag) 布局，自定义 ranker 保证了聚合节点和任务节点都在一层，一个节点的直接依赖更清晰。 DAGLayout 对自定义 ranker 的同层级节点之间的依赖进行了最少交叉连线优化，即使同层级节点依赖很多，展示也较清晰。

<br/>


**元素**: 由于在不同产品视觉风格不同，方案中导出了默认业务节点的注册逻辑 `registerInstanceNode` 和此节点对应的交互逻辑`setInstanceNodeStateStyles`。 用户可以直接引用，也可以在此基础上进行扩展形成符合自己业务产品的节点。默认方案中用颜色 + icon 来重点突出节点的状态，提升用户的图分析效率。

<br/>



**交互**:
-  click 节点：选中节点，一般配合侧边栏使用，可以显示当前节点的详细信息，并对节点进行更多操作
- hover 节点点击展开：展开一个节点的直接上/下游。
- hover 节点点击收起：收起一个节点的直接上/下游。
- click 聚类节点类型统计数字：快速展开对应分类的节点。
- hover 连线点击收起：收起节点的单个上/下游。
