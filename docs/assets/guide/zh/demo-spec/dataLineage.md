# 血缘图谱场景解决方案

## 场景介绍
数据加工处理的流程一般是从 RDS 和 MQ 开始，经过多次多种计算和存储，最终汇入指标、报表和数据服务系统。数据血缘描述了数据的来源和去向，以及数据在多个处理过程中的转换。能帮助用户更好地了解表，从而充分利用数据。组件使用文档请见[血缘图谱文档](../analysis-solution-spec/dataLineage)。
数据血缘图谱的主要场景有：


| 场景       | 用户关注 | 场景描述                                                     |
| ---------- | -------- | ----------------------------------------------- |
| 影响分析   | 下游     | 表生产者进行变更前，需要知道影响到下游的哪些表、字段、指标。 |
| 找数理解数 | 上游     | 从一个业务流程出发，理解表中字段的加工逻辑，找到贴合自身业务的数据。找到相同口径的表或字段，判断是否为冗余表，可以做下线处理。 |
| 链路梳理   | 链路     | 查看点到点的关系链路，多用于内审和数据治理。                 |
| 归因分析   | 上游     | 当某一个指标或字段数据/产出时间等出问题时，通过查看血缘上游的任务或资产，排查出造成问题的根因。 |
| 使用分析   | 下游     | 一个表的下游表越多，使用越频繁，可以认为价值越大。           |

## 场景编码

**元素**: 由于在不同产品视觉风格不同，节点内容差异较大。因此组件支持用 React 组件定制节点。详情可见`getTableContent` 配置项。


**交互**:
- click 节点：血缘图谱场景下由于数据众多，在默认视图下看清节点之间的链路关系还是比较困难的。组件默认添加了点击节点高亮节点到主节点的全部路径。让用户可以通过滚动定位在一屏中看清任意节点的链路关系。
- hover 连线：在血缘图谱场景下，连线不仅仅是表示两者之前的依赖关系，也是承载表之间加工逻辑关系的良好载体。因此组件支持定制 hover 连线的 tooltip 内容，详情可见配置项`getTaskTooltipContent`。
- click 筛选：根据用户关注的属性进行筛选，帮助用户更好的聚焦问题。
- click 分组：根据用户关注的属性进行分组，使结构更有条理更清晰。

## 设计思考
用户在使用过程中看重的是**查看关系的效率**和**属性的完备度**，因此在设计优化方案时会尽量从这两点出发去考虑。由于需要展示的表很多，依赖关系复杂，需要支持**万级数据和关系展示**，同时又要清晰的**展示全量数据和依赖关系**，普通的 DAG 图布局无法做到。这时候我们需要一个更紧凑清晰的数据呈现方式。

而说到紧凑的布局方式，自然而然我们就想到了列表。如果能用一个列表来承载层级血缘的节点，用连线来连接不同层级的节点表达节点之间的血缘关系。节点较多超出一屏时可以拖动此列滚动条来查看更多节点，连线随之刷新位置。当层级不满一屏时整体居中展示，层级过多超过一屏时可以左右滑动查看。这样在保留层级结构信息的同时最大程度的利用了可视区域，展示出了尽可能多的数据。
在查看局部的同时如果能对整体分布也有一定了解，能提升用户的使用效率。因此我们还在每列列表顶部增加了层级信息和节点统计，在筛选时也会有对应统计信息的更新。
