# 实例血缘-统计模式

## 场景介绍
数据加工处理的流程一般是从 RDS 和 MQ 开始，经过多次多种计算和存储，最终汇入指标、报表和数据服务系统。任务实例血缘描述了数据加工任务实例之间的相互关系。概括来说，任务实例血缘图的应用场景有三种：
- 关系展示：以用户关心的节点为中心，查看该节点的上下游依赖。
- 上游分析：当节点运行出现异常，向上追溯问题，关注的是**关系链路**。
- 下游分析：分析节点的下游影响面，此时关注的是**统计数据**。

统计模式对应第三种场景，当用户需要更改任务逻辑时，需要下游的统计信息来分析影响面，将变更同步到下游任务负责人。使用文档请见[实例血缘文档](../solutions/commonInst)。


## 设计思考
当做影响分析的时候，用户往往不关注单个明细节点数据，而是更需要统计数据。由于任务的实例一般很多(例如一个小时调度的任务，一天即可产生 24 个任务实例。一个任务实例的直接上游就可能有数万个节点)，如果平铺开来一个个数肯定不合适。此方案设计统计模式的初衷就是用一种更清晰高效的方式展示统计数据。用户可以直接展开多层任务下游，按照自身需求直接看一个总的统计节点，也可以按层级展示多个统计节点。统计节点可以使用 `getGroupData`按照需要的数据维度来分组展示。并且可以点击数量快速查看当前层级此维度数据的节点详情。

## 场景编码
**布局**: 采用了垂直布局，每层节点居中对齐，最大程度利用当前视窗空间的同时统计信息一目了然。

<br/>


**元素**: 统计模式方案中主节点也可定制，默认业务实例节点的注册逻辑为`registerInstanceNode` 和此节点对应的交互逻辑`setInstanceNodeStateStyles`。 用户可以直接引用，也可以在此基础上进行扩展形成符合自己业务产品的节点。单个统计节点形式较固定，因此直接内置了当前节点。用户也可以通过`setNodeStyles`自定义。

<br/>



**交互**:
- click 节点统计数字：展示该分组节点详情。
- click 分组查看详情：展示统计节点收起的所有节点信息。
